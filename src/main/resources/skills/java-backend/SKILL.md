# Java 后端面试统括策略

把整场面试视为证据收集，而不是知识点抽查。先建立候选人的事实基线，再验证机制和边界，最后验证生产可靠性。每一轮只推进一个明确的证据目标。

## 全局决策顺序

1. 以 JD 明确要求作为必考能力。
2. 以简历中的项目、技术和结果作为切入点，不把简历描述直接当成能力证据。
3. 用 `competencies.yml` 选择能力、证据目标、题型和追问轴。
4. 用 `stages.yml` 控制阶段归属；阶段是证据组织方式，不是固定题单。
5. 优先追问当前回答暴露的证据缺口；追问达到上限后切换能力。
6. 只有 Skill 策略允许且知识范围有效时使用 RAG；引用仅作为技术参照，不替候选人作答。
7. 用 `rubric.md` 评价证据质量，明确区分候选人事实与外部参考事实。

## 面试行为

- 从真实项目进入：确认场景、个人职责、约束和结果，再进入机制问题。
- 追问可判别证据：要求实现路径、失败现象、指标、替代方案或恢复过程。
- 根据回答改变下一题：优先补齐缺失证据，避免重复询问已经充分证明的内容。
- 难度体现在约束和推理深度，不体现在冷僻知识点。
- 对模糊指标追问测量口径；对团队成果追问个人决策与交付边界。
- 对生产方案追问失败检测、回滚、降级、监控和演进成本。

## RAG 使用边界

- `GENERATE_SCENARIO`：用参考资料构造贴近能力目标的故障或取舍场景。
- `VERIFY_FACT`：核对技术事实，识别回答与参考资料的一致或冲突之处。
- 问题引用和评价引用必须来自当轮检索快照。
- 无匹配、检索不可用或用途不允许时，继续使用 Skill 通用策略，不制造引用。

## 完成标准

整场面试结束时，每个进入 Plan 的能力都应有明确的已获得证据或缺失说明；报告能从阶段、问题、回答、评价和来源引用回溯结论。
