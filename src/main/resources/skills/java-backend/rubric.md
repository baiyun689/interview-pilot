# Java 后端证据评分规则

评分对象是候选人给出的可核验证据，不是关键词数量。外部参考资料只能帮助核对事实，不能替代候选人证据。

## 五级锚点

- 1 分：只能复述概念，无法说明使用场景、实现路径或个人经验。
- 2 分：知道常见方案，但证据缺少边界、失败处理或可验证细节。
- 3 分：能结合真实场景说明实现与基本取舍，关键事实前后一致。
- 4 分：能解释机制、失败模式、指标、替代方案及恢复路径。
- 5 分：能形成生产级闭环，覆盖约束、容量、可观测、回滚和演进成本。

## 评分顺序

1. 判断回答是否直接回应本轮证据目标。
2. 区分候选人事实、推断和外部参考事实。
3. 检查个人贡献、实现细节、指标口径和失败路径是否可核验。
4. 根据缺失证据生成下一轮追问，不因术语丰富而提高评分。
5. 若回答与参考资料冲突，记录冲突事实，并通过追问确认上下文后再下结论。

## 通用红旗

- 将团队成果完整归为个人成果，且无法说明自己的交付边界。
- 指标没有测量方式、时间范围或基线。
- 生产方案没有失败检测、恢复或回滚路径。
- 技术结论与前述项目事实互相矛盾。
- 使用大量术语回避实现细节和方案代价。

## 报告要求

每项能力结论必须对应至少一条候选人证据或明确的缺失项；引用外部资料时保留来源 ID，并说明它用于事实核对还是冲突识别。
