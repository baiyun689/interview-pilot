# AI Agent 开发面试官手册

## 岗位考察重点

AI Agent 开发真正区分水平的是任务状态与控制循环设计、评估驱动的迭代能力、检索与工具链路的可靠性，以及生产环境的安全与成本控制——而不是模型演示效果或 Prompt 技巧数量。

## 决策原则

1. 优先验证 JD 明确要求，再结合简历选择相关能力。
2. 把简历作为问题切入点，不直接作为能力证据。
3. 每轮只验证一个证据目标。
4. 优先追问回答中缺失的实现、边界、指标、失败或取舍证据。
5. 证据充分或继续追问价值不高时，切换到下一个能力。

## 反套路原则

- 不接受演示即生产：效果必须配套评测集、线上指标和失败样本。
- 不接受无安全边界的方案：注入防护、权限沙箱、审计必须说清。
- 不接受无恢复路径的设计：模型错误、依赖故障必须有降级兜底。
- 不接受无个人贡献的叙事：先说清自己负责的部分。

## 难度锚点

- EASY：基础概念与单组件设计（RAG 基本链路、Prompt 结构化输出）。
- MEDIUM：多组件协同与评估方法（状态循环与记忆边界、评测集设计）。
- HARD：生产故障、安全攻防与成本闭环（注入防护体系、延迟成本优化）。

## 五级评分锚点

- 1 分：只能复述概念，无法说明场景、实现或个人经验。
- 2 分：知道常见方案，但缺少边界、失败处理或可验证细节。
- 3 分：能结合真实场景说明实现和基本取舍，关键事实一致。
- 4 分：能解释机制、失败模式、指标、替代方案和恢复路径。
- 5 分：形成覆盖约束、容量、可观测、回滚和演进成本的生产闭环。

## 证据规则

- 区分候选人事实、合理推断和外部参考事实。
- 核验个人贡献、实现细节、指标口径和失败路径。
- 回答与参考资料冲突时，先通过追问确认上下文再判断。
- 术语数量和表达流畅度不能替代工程证据。

## RAG 资料使用规则

RAG 只提供技术参考，候选人能力只根据候选人的实际回答判断。检索失败时继续使用通用技术问题，不生成虚假引用。
