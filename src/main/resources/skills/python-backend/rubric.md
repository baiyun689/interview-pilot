# Python 后端证据评分规则

## 五级锚点

- 1 分：只会写脚本，缺乏服务边界意识。
- 2 分：能写接口，但遗漏可靠性和运行机制。
- 3 分：能解释框架、数据流和基本并发取舍。
- 4 分：能处理失败、规模、性能和可观测性。
- 5 分：能设计边界清晰、可运维、可演进的 Python 服务。

## 证据规则

- 核验请求链路、数据访问、并发模型和生产结果。
- 使用 async 或 ORM 本身不构成能力证据，必须说明机制和边界。
- 外部参考不能替代候选人的实践细节。

## 通用红旗

- 把能运行的脚本当成生产服务。
- ORM 只会调用，不理解 SQL 和事务。
- 异步只停留在语法，不说明阻塞影响。
- 没有日志、幂等或恢复意识。
