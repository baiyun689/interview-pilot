# 人工评审、反馈与通知

## 使用入口

- 企业账号：企业招聘 → 面试与评审。可查看回答、AI 逐题评估、冻结评分依据和知识证据；可指派评审人员。
- 人工评审可保存不完整草稿。正式提交后留下不可变修订；再次修改不会覆盖历史。引用的回答轮次必须属于本场面试。
- 招聘人员在授权岗位内、企业管理员可发布反馈；面试官只有明确指派后的评审权限，不能发布。
- 发布时选择已提交修订，单独填写候选人反馈，并预览确认。公开接口只返回发布版本、决定、反馈、发布时间。
- “进入下一轮”发布后，在岗位的面试批次中选择候选人，创建下一轮；“结束流程”将本次投递置为结束。
- 候选人：通知中心，以及面试邀请 → 查看企业反馈。未发布的意见、评分标准、知识原文不出现在候选人接口。
- 企业：通知记录，可查看邮件状态、失败原因及重试。状态未知时重发需明确确认，可能收到重复邮件。

## 一致性

V33 追加评审、历史修订、公开反馈、通知和投递尝试表，不修改 V27—V32。

企业写操作依次锁企业、投递、邀请；评审采用自己的乐观版本，首次保存使用 `version=-1`；公开反馈采用独立递增版本。并发发布同一版本只有一方成功。旧轮次不能覆盖已进入后续轮次的流程结果。

招聘文本与录音回答携带 `requestId`、`expectedTurnNo`、`sessionVersion`。幂等请求先重放原结果；新请求必须与服务端当前进度一致。请求指纹包括所绑定的进度，防止同一幂等键换题复用。个人练习保留旧请求兼容性。

实时语音连接绑定实际播放的题目及会话版本。旧连接提交不能写入新题；处理期间排队的重复确认、旧转写丢弃。换题切换识别回调代次，旧 ASR 回调不能附着到下一题。未完成确认的录音不当成正式答案。

## 邮件与提醒

业务变更与通知在同一事务持久化，邮件发送在独立后台线程执行，不占用面试超时扫描线程，也不持有业务长事务。邮件工作台账使用行锁、领取令牌及 120 秒租约，多实例只有一个发送者。

- 通知按收件人、邀请、事件、业务版本去重。
- 新邀请、日程调整、企业取消和反馈发布生成站内消息及邮件投递记录。
- 计划开始前默认 24 小时、1 小时提醒，`HIRING_REMINDER_HOURS` 可配置。安排时已错过的提醒不创建；重启后超过到期时间 5 分钟的旧提醒不补发。
- 发送前重新验证邀请状态与日程版本；改期、开始、拒绝、取消、结束后的旧提醒跳过。
- SMTP 成功仅代表 `ACCEPTED_BY_PROVIDER`，不代表候选人阅读。站内已读独立记录。
- 明确连接/认证失败最多自动尝试 3 次，退避 60/120 秒；发送超时或进程中断记为 `UNKNOWN`，不自动重发。
- 已交给 SMTP 的邮件无法撤回；通知入口始终指向最新站内日程。
- 邮件不含简历附件、内部评语、题库或完整反馈正文。

配置项在 `.env.example`。`HIRING_MAIL_ENABLED` 默认 `false`；未启用时站内消息照常可用，企业记录显示通道未启用。

## 本地邮件联调

无需外部邮箱，使用仓库提供的本地测试接收器：

```powershell
node scripts/local-mail-sink.mjs
```

接收器仅监听 `127.0.0.1:1025`，仅接受 `.test` 合成邮箱，不向外部转发。邮件原件写入被 Git 忽略的 `.codex-local/mail`。

另一终端启动后端：

```powershell
$env:HIRING_MAIL_ENABLED='true'
$env:SMTP_HOST='127.0.0.1'
$env:SMTP_PORT='1025'
.\gradlew.bat bootRun
```

真实部署时配置 SMTP 主机、端口、账号、密码、TLS、发件人及公开站点地址。当前已配置连接、读、写超时；配置依据 [Spring Boot 邮件文档](https://docs.spring.io/spring-boot/4.0/reference/io/email.html)。本轮未发送真实外部邮件。
